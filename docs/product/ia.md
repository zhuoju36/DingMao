# 信息架构（Information Architecture）

> 建工法律顾问 · 用户视角的"项目-场景-问诊"结构。
>
> **目标**：5-12 个场景 × 数十个项目规模下仍能快速找到工作入口。

---

## 一、核心架构决策

### 决策记录

| 决策 | 选项 | 最终选择 | 理由 |
|---|---|---|---|
| 场景是 Tab 还是顶级菜单 | 项目内 Tab / 跨项目顶级菜单 | **顶级菜单** | 5-12 场景时 Tab 横向溢出；律师按"任务类型"而非"项目"组织工作 |
| 项目列表形态 | 表格 / 卡片 | **卡片** | 卡片显示"每个项目的多场景状态快照"；表格难以表达 |
| 多次同场景问诊 | 强制新建 / 智能续聊 / 弹窗选择 | **弹窗选择** | 用户控制权最大；律师工作要审慎 |
| 报告展示位置 | 弹窗 / 聊天区卡片 | **聊天区卡片** | 弹窗关即丢；卡片内嵌不丢失 |
| 历史问诊展示位置 | 项目页底部 / 各场景 Tab 下 | **场景 Tab 下** | 合同审查和变更扯皮的 chat 不应混在一起 |

### MVP vs V3 演进路径

| 阶段 | 项目页结构 | 场景导航 |
|---|---|---|
| MVP（≤3 场景） | 项目页内 2-3 个 Tab（简化） | Dashboard 卡片入口 |
| V2（3-5 场景） | 项目页内 Tab + "更多场景"下拉 | Scenarios 顶级菜单（只读） |
| V3（5-12 场景） | 项目页 = 概览 + 场景卡片网格 | Scenarios 顶级菜单（可操作） |

## 三、URL 路由表

```
/                              → /dashboard
/login                         → Login 页

/dashboard                     → 首页
/projects                      → 项目列表（卡片网格 V3 / 表格 MVP）
/projects/new                  → 新建项目（modal 或独立页）
/projects/:id                  → 项目详情
  /projects/:id/consultations              → 该项目下所有问诊列表（V3 场景 Tab 内嵌时可省略）
  /projects/:id/scenarios/:scenario       → 场景 Tab（V3）
/projects/:id/edit             → 编辑项目（V2）

/scenarios                     → 场景中心（V2+）
/scenarios/:scenario           → 单场景跨项目视图
  /scenarios/:scenario/consultations     → 该场景下所有问诊（跨项目）

/consultations/:id             → 问诊聊天页（独立 URL，可直接访问）
/consultations/:id/report      → 报告独立页（可分享/打印，V3）

/docs                          → 知识库（V2）
/docs/standards/:id            → 单个强条（V2）
/docs/laws/:id                 → 单个法条（V2）

/settings                      → 个人设置（V2）
```

**设计原则**：
- 每个问诊有独立 URL（可分享、可书签）
- 项目和场景都有独立 URL（可深链）
- `/consultations/:id` 直接访问时无 history stack 安全回退（**修复 P0-1**）

## 五、UX 设计原则（约束后续开发）

1. **每个 AI 输出前都有免责条**（AGENTS.md 应用原则 4）
2. **每个问诊有独立 URL**（可分享、可刷新安全）
3. **每个操作有明确回退路径**（不依赖浏览器 history）
4. **多场景项目：Tab 是兜底（≤3 个），菜单是目标（≥4 个）**
5. **状态永远可见**：用户在任何页面都知道"系统在做什么 / 我下一步能做什么"
6. **新建 vs 续聊可选择**（用户控制权最大）

## 六、MVP 阶段实施优先级（与 UX 审计报告对齐）

按 ROI 排序：

| # | 任务 | 估时 | 来源 |
|---|---|---|---|
| 1 | 报告持久化（P0-2：嵌聊天区 + 免责条） | 2h | UX 审计 |
| 2 | 全局 Layout + 面包屑（P0-5） | 2h | UX 审计 |
| 3 | 历史问诊列表（P0-4） | 3h | UX 审计 |
| 4 | Dashboard 最近问诊（P0-3） | 2h | UX 审计 |
| 5 | 流式报告取消按钮（P0-5 流式版） | 1h | UX 审计 |
| 6 | 项目列表检索 + 中文角色（P1） | 1h | UX 审计 |
| 7 | 报告红黄绿配色（用 risk 三色类，P1-8） | 0.5h | UX 审计 |

**总计 MVP 优化 ≈ 11.5h**，按 4 天推进（每天 3h）。

## 七、未来扩展（V3 阶段）

1. **跨项目搜索**：Cmd+K 全局搜索项目/问诊/结论
2. **协作模式**：项目组成律师 + 监理 + 设计，多视角评论（**不在 MVP 边界**）
3. **智能提醒**：法律变更（如强条修订）自动推送
4. **离线缓存**：出差无网络也能查看历史报告
5. **OCR 上传合同图片**：自动识别扫描件（V2 强条库就绪后做）
